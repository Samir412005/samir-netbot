# الخصوصية وحدود الثقة

لا رقم هاتف/OTP في مخطط البيانات أو نماذج API؛ بيانات الربط: Telegram user ID وكود داخلي وجهاز. USSD قد يحوي بيانات حساسة يكتبها المستخدم بنفسه، لذا لا تعلم كوداً يحتوي رقم طرف آخر أو تحويل مال أو PIN. اكتمال صيغة USSD ليس تدقيقاً لمشروعيته أو سعره. موافقة المستخدم على الهاتف مطلوبة لكل استدعاء وليس عند الربط فقط.

التوكن 32 بايت عشوائية، hash SHA256 في الخادم، مشفر Android Keystore في الهاتف، لا backup. كود الربط 6 أرقام/5 دقائق/استخدام واحد مع حدود IP. هذا لا يمنع مهاجماً موزعاً من التخمين تماماً؛ أضف دفاعات بوابة وتأكيد جهاز عبر البوت قبل نشر واسع. حد محاولات التطبيق الحالي single-replica فقط.

الجهاز المرتبط يستطيع رفع رد مزيف؛ الرد المسجل دليل ما قاله العميل المصادق وليس شهادة موقعة من المشغل. لا تمنح مكافأة مالية على نتيجة USSD. قاعدة success يجب أن تكون مراجعة ومحددة، والعروض المتعلمة بلا قاعدة تأكيد لا تحصل على success تلقائي.

المستخدم يستطيع إيقاف الخدمة أو `/unlink DEVICE_ID`. لا تمنع Call أو SMS خارج التطبيق، ولا تحاول إلغاء USSD قيد التنفيذ بطرق غير رسمية. لا Accessibility ولا قراءة SMS ولا اعتراض OTP ولا SDK من المشغل.

لا تطبع request body أو Authorization في reverse-proxy أو APM. لا تخزن الرد الخام في crash analytics. النسخ الاحتياطية DB تحتوي Telegram IDs وردوداً مقنعة؛ تشفير وتقييد وصول ومدة احتفاظ مسؤولية المشغل. MVP لا يقدم حسابات إدارة ويب عامة، وعزل العرض الشخصي يجري على مستوى الخدمة وفلترة كتالوج البوت.
