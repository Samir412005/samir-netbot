# سمير نت — samir-netbot

MVP مستقل عن «إعلامي»: بوت تلجرام + تطبيق Android ينفّذ **USSD على شريحة صاحب الهاتف نفسه بعد موافقة صريحة لكل عملية**. التفعيل هو المسار الأساسي؛ النقاط والهدية ميزات ثانوية.

> **بلا وهم:** يوجد مسار استدعاء حقيقي لـ `TelephonyManager.sendUssdRequest`، لكن وجود الكود لا يضمن التفعيل 100%. الدعم يعتمد على الهاتف والشريحة والمشغل، والكود يجب أن يكون كاملاً single-shot. لا ندعم القوائم التفاعلية متعددة الخطوات ولا نؤتمت تأكيدات أو OTP. لا نعلن «تم التفعيل» لأن callback نجح فقط؛ نحتاج نص تأكيد مُراجع من المشغل. العروض الشخصية تعرض رد الشبكة وتُعلّم «لم يتأكد التفعيل» إلى أن يضبط المسؤول قاعدة تأكيد مناسبة.

## ما لا نطلبه
- لا رقم هاتف في البوت أو API. الربط بكود داخلي 6 أرقام يصدر من البوت؛ ليس OTP ولا كود المشغل.
- لا أكواد تحقق/تفعيل من تطبيقات المشغلين، ولا مفاتيحهم أو توكناتهم، ولا هندسة عكسية أو تجاوز حماية.
- لا تنفيذ USSD في السيرفر. التطبيق يستخدم واجهة Android الرسمية على هاتف المستخدم فقط.

## البنية
```
bot/       Python 3.11 + aiogram 3، عربي/فرنسي، إدارة الأوامر
api/       FastAPI، HTTPS، long-poll ومصادقة device_token
core/      SQLAlchemy، حالات الأوامر، النقاط والسجل
migrations/ Alembic؛ SQLite في التطوير، Postgres عند النشر المتقدم
android/   Kotlin، خدمة أمامية يبدؤها المستخدم + موافقة لكل USSD
scripts/   اختبار تكامل محاكى فقط، ليس كتالوج إنتاج
```
المسار: اختيار العرض → `queued` (pending) → تسليم مرة واحدة `delivered` (sent) → `success | fail | timeout` → إشعار البوت + `/history`. المهلة **نتيجة غير معروفة** وليست برهان عدم الخصم، ولا يعاد USSD تلقائياً. الرد المتأخر لا يحوّل المهلة إلى نجاح.

## التشغيل محلياً
```bash
python3.11 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# ضع التوكن من BotFather ومعرّفات مسؤولي Telegram؛ لا تضع أسراراً في Git
export DATABASE_URL=sqlite:///netbot.db
alembic upgrade head
# API على loopback للاختبارات فقط، تطبيق Android يرفض HTTP دائماً
ALLOW_HTTP_LOCAL=true uvicorn api.main:app --host 127.0.0.1 --port 8000 --no-access-log
# في طرفية ثانية مع متغيرات البيئة نفسها:
python -m bot.main
```
`python -m pytest -q` يشغّل اختبارات المنح، التكرار، الربط، المصادقة، العروض الشخصية، الجهاز المفقود/offline، الحالات والمهل. الاختبارات تحذف `test-netbot.db` فقط. لا يستعمل أي اختبار شريحة أو شبكة مشغل.

## نشر HTTPS (Docker Compose)
1. VPS + دومين موجّه له، افتح 80/443، وثبّت Docker Compose.
2. عدّل `.env`: `BOT_TOKEN`, `ADMIN_IDS`, `API_DOMAIN=api.your-domain.tld`, `DATABASE_URL=sqlite:////data/netbot.db`, `ALLOW_HTTP_LOCAL=false`.
3. `docker compose up -d --build`، ثم `curl https://api.your-domain.tld/health`.
4. افتح التطبيق وأدخل **نفس عنوان HTTPS الموثوق**، و`/pair` في البوت؛ أدخل كود الربط في التطبيق خلال 5 دقائق. لا ترسل الكود لأي شخص.
5. امنح CALL_PHONE وREAD_PHONE_STATE (لاختيار SIM بلا قراءة رقمها)، واسمح بالإشعارات. اختر الشريحة ثم «بدء الاتصال» من واجهة التطبيق. الخدمة لا تبدأ خفية أو بعد إعادة الإقلاع.
6. اختر عرضاً في البوت. افتح إشعار التطبيق وراجع الكود والعرض والشريحة والتكلفة عند المشغل ثم وافق أو ارفض. تابع النتيجة في البوت و`/history`.

خادم API غير مكشوف مباشرة خارج شبكة Compose؛ وحده Caddy يمرر HTTPS. `forwarded-allow-ips=*` مقصود فقط داخل هذه الشبكة الموثوقة؛ **لا تنشر منفذ uvicorn مباشرة**. على نشر مختلف حدّد IP البروكسي ولا تثق بهيدر من الإنترنت. شغّل نسخة API واحدة ونسخة bot واحدة في MVP. حد محاولات الربط داخل العملية (5/5 دقائق/IP)؛ قبل التوسع استعمل Redis وحدود بوابة ومراقبة تخمين الأكواد. نفّذ نسخاً احتياطية مشفرة للـvolume.

## تعليم الكود — بلا انتظار كتالوج رسمي
من التطبيق: «أضف عرضاً» → الاسم + المشغل + USSD الذي تعرفه وتستعمله يدوياً → وافق على إرسال هذه البيانات فقط. يصبح العرض **شخصياً لحسابك فقط** في زر «عروض الإنترنت» وبسعر نقاط صفر. الحفظ لا يطلب إذن مكالمة ولا ينفذ الكود. التنفيذ من البوت لاحقاً يحتاج موافقة ثانية على الهاتف. لا تشارك أكواداً تتضمن بيانات أشخاص أو عمليات تحويل؛ أنت مسؤول عن التكلفة وصحة الكود. يقبل MVP صيغة USSD رقمية تنتهي بـ# فقط ولا يقبل قوائم خطوات أو نص OTP.

## إدارة الكتالوج
`/admin` متاح في الخاص لمعرّفات `ADMIN_IDS` فقط:
```
/admin add اسم العرض|المشغل|الحجم|0|internet|الكود الرسمي|نص تأكيد التفعيل
/admin enable BID
/admin disable BID
/admin requests
/admin ban TELEGRAM_ID
/admin unban TELEGRAM_ID
```
إضافة العرض تكون معطلة افتراضياً؛ عدّل الكود بإضافة عرض جديد وتعطيل القديم للحفاظ على سجل الأوامر السابقة. `success_regex` يدعم أنماطاً بسيطة فقط؛ راجع عبارة نجاح فعلية محددة وليس «OK» عاماً. يجب أن تعرف التكلفة المالية وتذكرها في اسم/وصف العرض قبل النشر. لا يوجد بيع رصيد؛ النقاط ليست أموالاً ولا رصيد المشغل. إذا وضع المسؤول سعر نقاط فالحجز عند الطلب، دون استرداد آلي في MVP؛ ننصح بسعر 0 لمسار التفعيل.

الأمثلة التالية **قوالب غير قابلة للتنفيذ وليست أكواداً صحيحة لأي مشغل** (لا تستبدل XXX عشوائياً):
| العرض الوهمي | المشغل | القالب |
|---|---|---|
| إنترنت يومي | مشغل A | `*XXX*DAY#` |
| إنترنت أسبوعي | مشغل A | `*XXX*WEEK#` |
| إنترنت شهري | مشغل B | `*XXX*MONTH#` |
| عرض خاص | مشغل C | `*XXX*SPECIAL#` |
لا تُزرع هذه العروض في الإنتاج. `*000*000#` يظهر فقط في اختبارات المحاكاة؛ **لا تجربه على شريحة حقيقية**.

## API
- `POST /device/register` `{code, name}` → device_id + device_token عشوائي 256-bit؛ يعرض مرة واحدة، يخزن السيرفر hash فقط، والكود يُستهلك مرة واحدة.
- `GET /device/commands` مع `Authorization: Bearer ...` → long-poll حتى 20 ثانية.
- `POST /device/result` `{command_id, outcome: response|fail|timeout, response}`، تكرار نفس النتيجة لا يعيد التنفيذ ولا يغير الحالة النهائية.
- `POST /device/offers` `{name, operator, ussd, idempotency_key, consent:true}` → عرض خاص لصاحب الجهاز فقط.
- `GET /health`، و`/docs` لتفاصيل OpenAPI.

الـdevice_token مشفر في الهاتف عبر Android Keystore (AES-GCM). Android backup معطّل. `/unlink ID` يبطل التوكن من جهة السيرفر. ضغط «إيقاف» في التطبيق يوقف الاتصال والتفويض؛ عملية أرسلت بالفعل للشبكة قد لا يمكن إلغاؤها. السيرفر يقنّع الأرقام في رد الشبكة ولا يسجل access logs، ولا يطبع token أو الكود في اللوغ. سجل العمليات يحفظ الحالة والسبب والرد المقنّع (لا الرد الأصلي المحتوي على رقم كامل). اجعل الاحتفاظ بالردود محدوداً حسب سياسة خصوصية الاستضافة.

## APK وGitHub Actions
كل push إلى main: pytest + Alembic + بناء Kotlin + lint + اختبار HTTPS حقيقي بين API وعميل Kotlin المشترك مع التطبيق؛ **طبقة الاتصالات الخلوية محاكاة**، لا جهاز ولا emulator. ينتج `simulation-proof.json` و`pytest-output.txt` وينشر APK مع SHA256 وتقرير التوقيع في GitHub Releases (prerelease).

بناء محلي: JDK17 + Android SDK35 + Gradle8.9 ثم `cd android && gradle testDebugUnitTest lintDebug assembleDebug`.
للتوقيع الإنتاجي أنشئ مفتاحاً **جديداً مستقلاً**:
```bash
keytool -genkeypair -keystore netbot.jks -alias netbot -keyalg RSA -keysize 3072 -validity 10000
base64 -w0 netbot.jks | gh secret set KEYSTORE_B64 --repo Samir412005/samir-netbot
# ضع كلمة مرور store/key المتطابقة في SIGNING_PASSWORD، ولا تنشرها أو تحفظها في المستودع
```
دون هذين السرين ينشر Actions **APK تجريبياً موقّعاً بمفتاح debug**، package منفصل `com.samir.netbot.preview`، ليس توقيعاً إنتاجياً ثابتاً. مفاتيح debug للـCI قد تتغير بين البناءات؛ قد يلزم حذف النسخة التجريبية قبل تحديثها. لا نعيد استعمال مفتاح مشروع إعلامي.

## حدود ومخاطر صريحة
- لا ضمان 100% لـ«أي عرض». قد يرفض Android/OEM/Multi-SIM `sendUssdRequest`، أو يحتاج العرض حواراً تفاعلياً غير مدعوم؛ توقف ولا تتحايل.
- لم نتحقق من تفعيل حقيقي لدى مشغل أو من خصم رصيد، ولم نرسل رسالة Telegram فعلية بدون BOT_TOKEN من المالك.
- لا يُنشر خادم إنتاج تلقائياً. يلزم دومين وVPS وتوكن BotFather. وجود GitHub Release ليس تشغيل البوت.
- النص المطابق يؤكد رد الشبكة فقط، وليس تسوية فوترة مستقلة؛ الهاتف وصاحب التوكن جزء من حدود الثقة ويمكن لجهاز معدل تزوير رد.
- انقطاع الشبكة قد يفقد الرد. لا إعادة تلقائية لـUSSD؛ سياسة at-most-once مقصودة لتقليل الخصم المكرر، لا ادعاء exactly-once عبر شبكة المشغل.
- تشغيل الخدمة الأمامية يتطلب بدء المستخدم. Doze/توفير البطارية قد يقطع الاتصال. specialUse يحتاج إفصاحاً ومراجعة إن نُشر في Google Play؛ هذا التسليم sideload، وليس اعتماد Play.
- شروط المشغل والقانون المحلي والأسعار يلزم مراجعتها من المالك؛ لم نحصل على إذن تجاري أو وعد خدمات مجانية.
- Postgres: غيّر DATABASE_URL إلى `postgresql+psycopg://...` وشغّل Alembic على قاعدة جديدة، ثم انقل البيانات بخطة مدققة. لا يوجد ترحيل بيانات SQLite آلي، ولم تختبر Postgres هنا.
